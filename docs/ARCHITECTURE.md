# MELTTOWN Frontend Architecture Guide

Based on [Bulletproof React](https://github.com/alan2207/bulletproof-react) principles, customized for MELTTOWN.

## Rules

### 1. Feature-First Architecture

Each feature is a self-contained module. A feature owns its components, hooks, stores, API calls, utils, and types.

```
features/fire-map/             # Everything related to fire + map
features/landing/              # Everything related to landing page
```

**Rule**: Features MUST NOT import from other features. If two features need shared logic, extract it to `src/components/`, `src/hooks/`, `src/lib/`, or `src/stores/`.

### 2. Import Rules

#### Path Alias

Use `@/` alias for absolute imports from `src/`:

```typescript
// Good
import { Button } from '@/components/Button'
import { useGeolocation } from '@/features/fire-map/hooks/useGeolocation'

// Bad
import { Button } from '../../../components/Button'
```

#### Import Order

```typescript
// 1. React / external libraries
import { useState } from 'react'
import { MapContainer } from 'react-leaflet'

// 2. Shared modules (@/components, @/hooks, @/lib, @/stores, @/types)
import { Button } from '@/components/Button'
import { socket } from '@/lib/socket'

// 3. Feature-local imports (relative)
import { FireOverlay } from './FireOverlay'
import { useFireMap } from '../hooks/useFireMap'
import { useFireStore } from '../stores/fireStore'
```

#### Import Restriction Matrix

| Source | Can import from |
|--------|----------------|
| `features/X/components` | Same feature's hooks, stores, api, utils, types + shared modules |
| `features/X/hooks` | Same feature's api, stores, utils, types + shared modules |
| `features/X/stores` | Same feature's types + shared modules |
| `features/X/api` | Same feature's types + shared modules |
| `routes/` | Any feature's components (thin composition layer) |
| `components/` | `hooks/`, `lib/`, `types/` only |
| `stores/` (global) | `lib/`, `types/` only |

### 3. Naming Conventions

#### Files & Directories

| Type | Convention | Example |
|------|-----------|---------|
| Component | PascalCase | `FireButton.tsx` |
| Hook | camelCase with `use` prefix | `useGeolocation.ts` |
| Store | camelCase with `Store` suffix | `fireStore.ts` |
| Utility | camelCase | `getGridId.ts` or grouped in `utils.ts` |
| Type | camelCase | `types.ts` or `types/index.ts` |
| Route | kebab-case (TanStack convention) | `map.tsx`, `__root.tsx` |
| Directory | kebab-case | `fire-map/`, `components/` |

#### Code Identifiers

| Type | Convention | Example |
|------|-----------|---------|
| Component | PascalCase | `FireButton`, `MapPage` |
| Hook | camelCase with `use` | `useFireMap`, `useCooldown` |
| Zustand store | `use___Store` | `useFireStore`, `useSocketStore` |
| Type / Interface | PascalCase | `FireEvent`, `GridCell` |
| Enum | PascalCase | `FireStage` |
| Constant | UPPER_SNAKE_CASE | `GRID_SIZE`, `TTL_SECONDS` |
| Function | camelCase | `getGridId`, `getFireStage` |

### 4. Component Patterns

#### Structure

```tsx
// 1. Imports
import { useState } from 'react'
import { useFireStore } from '../stores/fireStore'

// 2. Types (if component-specific)
interface FireButtonProps {
  onFire: () => void
  disabled: boolean
}

// 3. Component (named export, not default)
export function FireButton({ onFire, disabled }: FireButtonProps) {
  // hooks first
  const cooldown = useFireStore((s) => s.cooldown)

  // handlers
  const handleTap = () => { ... }

  // render
  return (...)
}
```

**Rules:**
- Always use **named exports** (no `export default`)
- One component per file
- Props interface defined in the same file unless shared

### 5. State Management Strategy

| State Type | Tool | Where |
|-----------|------|-------|
| Server state (API data) | TanStack Query | `features/X/api/` |
| Client state (UI, fire, grid) | Zustand | `features/X/stores/` |
| Global client state (socket) | Zustand | `src/stores/` |
| URL state (route params) | TanStack Router | `src/routes/` |

#### Zustand Store Pattern

```typescript
import { create } from 'zustand'
import type { FireEvent } from '../types'

interface FireState {
  fires: Map<string, FireEvent[]>
  cooldownEnd: number | null
  addFire: (gridId: string, event: FireEvent) => void
  setCooldown: (end: number) => void
}

export const useFireStore = create<FireState>((set) => ({
  fires: new Map(),
  cooldownEnd: null,
  addFire: (gridId, event) =>
    set((state) => {
      const next = new Map(state.fires)
      const existing = next.get(gridId) ?? []
      next.set(gridId, [...existing, event])
      return { fires: next }
    }),
  setCooldown: (end) => set({ cooldownEnd: end }),
}))
```

### 6. Socket.io Integration

```
Socket events → Zustand stores → React components re-render
```

- Socket client singleton lives in `src/lib/socket.ts`
- Socket event listeners update Zustand stores
- Components subscribe to Zustand stores (not socket directly)
- Socket connects on map page mount, disconnects on unmount

### 7. Route Definitions

Routes are thin composition layers. They import a feature's page component and render it.

```tsx
// src/routes/map.tsx
import { createFileRoute } from '@tanstack/react-router'
import { MapPage } from '../features/fire-map/components/MapPage'

export const Route = createFileRoute('/map')({
  component: MapPage,
})
```

**Rule**: No business logic in route files. Route files only compose and configure.

## Hard Rules Summary

1. **No cross-feature imports** — extract to shared if needed
2. **Named exports only** — no `export default`
3. **One component per file**
4. **Zustand for client state, TanStack Query for server state**
5. **Socket events flow through Zustand stores, not directly to components**
6. **Routes are thin composition layers**
7. **Use `@/` path alias for imports outside current feature**
8. **Types live with their feature unless shared**
9. **Constants in UPPER_SNAKE_CASE in `lib/config.ts`**
10. **Mobile-first Tailwind — base styles are mobile, use `md:` / `lg:` for larger**
